# 32 点大曲面连续扫描速度规划 V1 验收报告

## 结论

当前软件已完成从 32 个扫描位姿到容差受控平滑、确定性速度规划、连续 IK/FK 约束、RoboDK 原生 `MoveL` 导入和高精度 URScript 导出的闭环。最终平滑变速方案在 RoboDK 1 倍离线播放中耗时 204.0856 s，比原始逐点停止方案的 252.9568 s 缩短 19.32%，比平滑固定速度方案的 209.7092 s 缩短 2.68%。

该结论只适用于当前站点模型与仿真实验参数。实机执行和扫描质量不属于 V1 验收范围。

## RoboDK 导入阻断分析

用户截图中的阻断并非速度规划不可行，而是导入层无法证明扫描仪坐标语义：当 `scanner-to-tool extrinsic` 缺失、未经验证，或保存的站点／工具／参考系与当前 RoboDK 不一致时，软件拒绝生成程序。这一保护不能通过伪造验证标志绕过。

V1从当前活动站点读取 `UR10`、`Frame 2` 和 `Creaform MetraSCAN` 的实际关系，并保存为站点绑定的 `station_verified` 映射。导入前再次比较实时工具、参考系、机器人基座和工件变换；当前案例的映射位置／姿态差均为0，因此允许离线导入。`physical_calibration_validated=false` 继续保留，表示该结果不是实物外参标定。

## 方法与数据契约

输入为程序 A 的 32 个扫描位姿。路径平滑使用 Yang2020 位置角点样条内核，并以共享基函数完成姿态工程适配；姿态误差按 SO(3) 角距离审计。密集路径随后按位置和姿态双误差预算压缩到 330 个位姿。

速度规划使用确定性 TCP 前后向算法，再以连续 RoboDK IK/FK 得到的 q(s) 对六轴速度和加速度进行重定时。参考计划 CSV 记录节点状态和离开段时间；命令 CSV 单独记录进入目标点的段速度、加速度与 rounding，避免首尾零节点速度和执行指令混淆。

RoboDK 程序保留原生 `MoveL`：首次接近使用 `MoveJ`，扫描内部点使用非零 rounding，末点 rounding 为 0。导出器保存原后处理结果，同时生成不丢失亚毫米 rounding 的高精度 URScript。

## 验收证据

- 坐标语义：实时站点核对工具、参考系和基座变换，位置与姿态映射误差均为 0；`physical_calibration_validated=false` 被保留。
- 程序有效性：A/B/C 的 RoboDK `Update` 有效率均为 1.0。
- 原生轨迹：三组 `InstructionListJoints` 均返回 `Success`、错误码 0，本轮仿真关节速度／加速度限值检查通过。
- 连续结构：B/C 内部 rounding 最小 0.049 mm，末点为 0；程序由速度、rounding、Move 指令组成，无 Pause 指令。
- 导出一致性：高精度脚本中的 rounding 与命令表一致，330 个运动位姿顺序一致。
- 几何误差：基于实际播放观测关节的站点模型 FK，B/C 最大位置误差 0.7354 mm、最大姿态误差 1.2546°。

## 局限与后续

旧版 RoboDK 4.0 的播放时间、`Update` 周期与轨迹采样时间不一致，因此效率只采用同一条件下的 1 倍实际播放时间；不以 `Update` 或轨迹 dt 替代。内部非零 rounding 证明程序没有命令逐点停止，但不等同于控制器层瞬时速度测量。

V1 尚未验证碰撞、扭矩、UR 控制器插补、实物标定、扫描质量和 UR10 实机安全限值。进入实机阶段前，需要重新确定速度、加速度、位置和姿态容差，并完成工具外参和扫描质量验证。
