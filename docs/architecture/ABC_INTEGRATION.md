## 保留的算法与参数

- 食物源为节点排列；保留雇佣蜂、观察蜂、基于 trial/LIMIT 的侦察蜂阶段。
- 保留 swap、insert、2-opt 反转邻域和适应度贪婪选择。
- 保留欧氏距离矩阵、折点角度统计、组合目标与原版 1.5 倍交叉惩罚。
- `config.ABCConfig` 的默认值未改动：60 个食物源、LIMIT=150、35000 次评估、
  固定种子 2025、自由端点开路径、30° 折点阈值、权重 `(1/150, 0)`。
- 结果仍包含 `best_tour`、`best_length`、`best_corners`、`best_objective`
  及三个历史列表。`best_tour` 是每个索引恰好一次的排列；闭环长度包含返回首点的边，
  返回排列不会重复首点。本应用界面默认使用开路径。

## 集成修补

1. 移除未使用的 `deap`、`sys`、`true_divide` 导入，移除独立示例数据和未使用的
   自由函数，避免运行示例或携带无关依赖。求解核心只需要 NumPy。
2. `progressbar` 和 Matplotlib 按配置可选导入；缺少它们时仍可求解。
   Matplotlib 使用独立 Figure/Agg canvas 保存图片，不切换全局后端或使用 pyplot。
   求解异常、写文件异常仍会传给既有界面错误回调，不以其他算法代替结果。
3. 无论只绘制历史还是同时绘制路径，都先创建输出目录；自由端点路径使用实际
   首尾节点标记起终点。默认 `viz_frames/` 作为生成产物忽略，不纳入版本控制。
4. 使用实例内 `random.Random` 和 `numpy.random.RandomState`；保留固定种子的
   原随机数序列，避免后台 ABC 修改应用全局随机状态或被另一实例干扰。
5. 验证点数组形状、有限值、正整数预算、角度、权重和端点；评估预算至少覆盖
   全部食物源的初始化，非法配置抛出 `ValueError`。支持单点、重合点、两点，
   以及独立固定起点/终点；可排列节点不足两个时无需进入蜂群迭代。
6. 侦察蜂之后立即更新全局最优，确保最后一次允许评估得到的更优路径能够返回。
   这会修正原版少数运行的返回值及历史记录，不承诺所有运行逐项复现原版缺陷。

## 目标函数的边界

`best_length` 和 `history_length` 是真实三维折线长度，单位沿用输入点（应用内为 mm）。
`best_objective` 是长度/折点组合目标，长度部分可能乘原版交叉惩罚。
两者不能直接混用。

为保留原算法，本次未重新设计交叉检测：它使用 XY 平面投影，并保留原版开路径
首尾边组合跳过规则，不能解释为完整三维自交检测、避障、机器人可达性或扫描质量验证。
如果后续要用于正式算法对比，应单独确定目标函数与交叉检测协议。
